# prereject

**보내기 전에, AI 심사위원 팀이 당신을 먼저 떨어뜨려 봅니다.**

지원서·사업계획서·자기소개서·피치덱을 붙여넣으면, "통과할까?"가 아니라
**"왜 반려될까?"**를 찾아 반려 이유 + 그대로 붙여넣을 수정 문구를 돌려줍니다.

> 핵심 사상: 내부 점수는 **개선 엔진**이지 당락 예측기가 아니다.
> 점수가 몇 점인지가 아니라, 그 점수가 **어디를 고쳐야 하는지 가리키는가**가 전부다.

## 무엇을 하나

- **이중 채점** — 절대점수 + 경쟁 컷("평범하면 컷").
- **탈락사유 헌터 (E1~E8)** — 배점표 밖에서 실제로 떨어뜨리는 요인(자격·형식·자기파괴적 서술·미구현 과장·근거 없는 수치·평범함). 기본 판정은 CUT.
- **그대로 붙여넣을 수정 문구** — 약점을 "검증 계획"으로 프레이밍(정직 ≠ 자기비하).

## 실행

```bash
npm install
cp .env.example .env.local   # ANTHROPIC_API_KEY 또는 OPENAI_API_KEY 중 하나
npm run dev                  # http://localhost:3000
```

## 입력 형식

제출물은 **파일로 올리거나** 직접 붙여넣는다.

| 형식 | 보존되는 구조 |
|---|---|
| PDF | 쪽 경계 (`[3쪽]`) |
| PPTX | 슬라이드 + 발표자 노트 (`[슬라이드 5]`, rels 기반 매핑) |
| DOCX | Word가 기록한 페이지 나누기가 있을 때만 쪽 분리 |
| HWP (한글 5.x) | 실제 쪽 경계 (rhwp 조판) |
| HWPX | 구역 |
| TXT / MD | 그대로 |

🔴 **파싱은 전부 브라우저에서 한다.** 파일 자체는 서버로 전송되지 않고, 추출된 텍스트만 심사 API로 간다.
사업계획서·피치덱이 민감 문서라는 점과, Vercel 함수 바디 상한(4.5MB)을 동시에 해결하는 선택이다.

왜 구조를 보존하나: 덱을 평문으로 뭉개면 "4쪽에 글이 몰려 있다", "마지막 장에 투자 요청이 없다" 같은
반려사유를 **원리적으로** 찾을 수 없다. 심사위원은 장 단위로 본다. 장별 글자 수는 클라이언트가
결정론적으로 세어 모델에 함께 넘기고(추론이 아니라 계산), 모델은 각 반려사유에 `location`을 붙인다.


### 한글 문서(.hwp)

한글 바이너리는 [rhwp](https://github.com/edwardkim/rhwp)(MIT, Rust/WASM)로 브라우저에서 조판해 읽는다. 8 MB WASM 이라 **한글 파일을 올릴 때만** 내려받는다(동적 import).

🔴 `getPageText()` 를 쓰지 않는다 — 본문 문단만 주고 **표 안 글자를 통째로 빠뜨린다**. 실측(16쪽 신청서): `getPageText` 2,417자 vs 조판 레이아웃 21,458자. 한국 신청서는 대부분 표라서 그 경로로는 89%를 잃는다. `getPageTextLayout()` 의 TextRun 을 y 좌표 변화로 줄바꿈 복원해 쓴다.
